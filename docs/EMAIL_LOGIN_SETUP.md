# تشغيل تسجيل الدخول بالبريد — MINJAZ

## الحالة

تمت إضافة تسجيل الدخول بالبريد إلى العميل والمستقل ولوحة الإدارة في فرع
`feature/digital-services-geidea-sandbox` فقط. لا يُرسل أي بريد حقيقي حتى
يُربط حساب إرسال معتمد. لم تُفعّل المدفوعات ولم يتأثر الإنتاج.

## اختيار الإرسال (الموصى به: Resend API)

Railway يمنع SMTP على Free/Trial/Hobby. استخدم مزود HTTPS مثل
[Resend](https://resend.com)؛ لا تحتاج سجلًا تجاريًا **للترابط التقني**،
لكن قد تتطلب الخدمة إثبات ملكية نطاق البريد.

1. سجّل في Resend وأنشئ **API key بصلاحية sending**.
2. للتجربة المحدودة يمكن استخدام `onboarding@resend.dev` وفق قيود Resend
   على المستلمين؛ إرسال رموز الدخول لعملاء متعددين يحتاج نطاقًا تملكه
   وتوثّقه في Resend مع سجلات SPF/DKIM.
3. في مشروع Railway **MINJAZ-DIGITAL-SERVICES-TEST**، خدمة
   `minjaz-digital-services-api`، البيئة `sandbox` فقط، جهّز المتغيرات
   التالية عبر **Variables** (لا تضع مفاتيح API في GitHub أو هنا):

   - **مضبوطان مسبقًا في sandbox:** `EMAIL_MODE=resend` و
     `EMAIL_FROM=onboarding@resend.dev` للاختبار المحدود.
   - **مطلوب منك:** `RESEND_API_KEY=<your secret sending-only key>`
   - **مطلوب منك:** `ADMIN_EMAIL=<your verified administrator mailbox>`
   - لاحقًا، للتسليم إلى جميع العملاء، غيّر `EMAIL_FROM` إلى
     `login@your-verified-domain.com` بعد توثيق نطاق تملكه.

4. يوجد مسبقًا `AUTH_SECRET` عشوائي طويل في Railway sandbox؛ لا
   تستبدله دون حاجة، لأن تغييره ينهي صلاحية الجلسات الحالية.
5. أعد نشر خدمة sandbox بعد الحفظ. افتح
   `/api/v1/auth/email-status`؛ متى كان `configured:true`
   تصبح واجهة إرسال الرمز جاهزة للاختبار.
6. جرب الطلب من `/` واللوحة `/digital-services/admin` باستخدام بريد
   تملكه؛ يجب وصول رمز مؤقت من ست خانات وصلاحيته عشر دقائق.
7. اختبر محاولات الرمز الخاطئ، وإعادة الاستخدام، واختلاف بريد المدير
   عن حساب العميل والمستقل. لا تفعّل الإنتاج قبل الاختبار.

## SMTP (بديل لخطة Railway Pro وما فوق)

الكود يدعم أيضًا `EMAIL_MODE=smtp` مع متغيرات:
`EMAIL_FROM`, `SMTP_HOST`, `SMTP_PORT` (465 أو 587),
`SMTP_USERNAME`, `SMTP_PASSWORD`, `AUTH_SECRET`.
لا تختَر SMTP على Free/Trial/Hobby لأن Railway يمنع اتصالات SMTP الصادرة
فيها. لا تستخدم كلمة مرور البريد الأساسية؛ استخدم كلمة مرور تطبيق أو
اعتمادات مخصصة آمنة عندما يسمح المزود.

## الحماية والتوافق

- **رموز البريد لا تُعاد للمتصفح** حتى في sandbox؛ تصل فقط للبريد الفعلي.
- لكل رمز عمر 10 دقائق، وخمس محاولات خاطئة كحد أقصى، وحد 5 طلبات رمز لكل
  بريد في عشر دقائق وفاصل دقيقة بين الطلبات، بالإضافة إلى تقييد مصدر الطلب.
- يتم تخزين بصمة HMAC للرمز بدل حفظ الرمز؛ يتم استهلاكه مرة واحدة
  داخل معاملة PostgreSQL.
- صلاحيات المدير تنشأ فقط عند التحقق من **البريد المطابق تمامًا
  لـ `ADMIN_EMAIL`** وبوجود مزود إرسال حقيقي. العميل والمستقل لا
  يستطيعان تحديد `role=admin`.
- بيانات المستخدمين الذين دخلوا بالجوال سابقًا تبقى محفوظة،
  **لكن الحسابات الجديدة بالبريد لا تُدمج تلقائيًا** مع حسابات الجوال.
  قبل نشر تسجيل البريد على بيانات عملاء حقيقيين، أضف تدفق ربط
  البريد بحساب موجود أثناء جلسة دخول موثّقة.
- اتصال SMS القديم لم يُحذف من الخادم حرصًا على توافق الحسابات
  القديمة والتجارب؛ واجهات الدخول الجديدة تفضّل البريد.
- إذا ظهر `email_not_configured`، فخدمة البريد لم تُفعَّل، وليس
  هناك رمز سري أو تجاوز بديل.
- `PAYMENT_MODE=mock` ولا يوجد خصم مالي ضمن مسار الدخول.

## نقاط API

- `GET /api/v1/auth/email-status` — يُظهر الجاهزية دون أسرار.
- `POST /api/v1/auth/request-email-otp` — يقبل
  `{"email":"user@example.com","role":"client"}`
  أو `freelancer`. لا يقبل admin من العميل.
- `POST /api/v1/auth/verify-email-otp` — يقبل
  `{"challenge_id":"UUID","code":"123456","name":"اسم المستخدم"}`
  ويصدر جلسة HttpOnly للمتصفح بعد التحقق.

**المصدر:** [Railway outbound networking](https://docs.railway.com/networking/outbound-networking).
