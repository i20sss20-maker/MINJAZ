# خدمات منجاز الرقمية — دليل البيئة التجريبية

> **بيئة معزولة للتجربة فقط.** لا تنقل الفرع إلى الإنتاج ولا تفعّل الدفع الحقيقي قبل اختبار مستقل ومراجعة أمنية.

## الروابط

- متجر العميل: https://minjaz-digital-services-api-sandbox.up.railway.app/digital-services
- لوحة الإدارة: https://minjaz-digital-services-api-sandbox.up.railway.app/digital-services/admin
- فحص الخادم: https://minjaz-digital-services-api-sandbox.up.railway.app/health
- الفرع: `feature/digital-services-geidea-sandbox` داخل مستودع `i20sss20-maker/MINJAZ`.

## الخطوات المقترحة لاختبار الحسابات

1. ادخل إلى موقع التجربة، وسجّل الدخول بحساب عميل تجريبي.
2. افتح الخدمات الرقمية، واختر تصنيفًا، وابحث عن خدمة.
3. اضغط «اطلب الخدمة»، واكتب متطلبات لا تقل عن 10 أحرف. سينشئ النظام **مسودة بلا دفع**.
4. اعرض طلباتك وتفاصيل الطلب. يمكن تعديل المتطلبات أو إلغاء المسودة **قبل بدء التنفيذ فقط**.
5. افتح لوحة الإدارة بحساب مدير تجريبي، وابدأ تنفيذ المسودة.
6. من صفحة الطلب أضف رابط HTTPS إلى ملف موجود مسبقًا، مثل ملف على مزود تخزين. يبقى الرابط **محجوبًا عن العميل حتى التسليم**. يمكن سحبه قبل نشره.
7. سلّم الخدمة بملاحظة واضحة لا تقل عن 10 أحرف. تظهر الروابط التي لم تُسحب للعميل.
8. جرّب طلب تعديل من حساب العميل؛ يعود الطلب للتنفيذ، ويُحجب أي رابط جديد حتى التسليم التالي. يتوقف التعديل عند الحد المتفق عليه عند إنشاء الطلب.
9. اعتمد الاستلام من حساب العميل، وراجع سجل الأحداث وتحديثات الطلبات.
10. من لوحة الإدارة أخفِ إحدى الباقات التجريبية، ثم راجع القائمة العامة. **النشر التالي لا يعيد إظهار الباقة المخفية**.

## ما تدعمه المنظومة

- باقات مختلفة مع سعر ومدة تنفيذ وعدد مراجعات.
- مسودات طلبات مع منع التكرار بواسطة مفتاح خاص لكل محاولة، وسعر متفق عليه لا يتغير إذا تغيّر سعر الباقة لاحقًا.
- صلاحيات مدير وعميل، وملكية الطلب، وسجل مراحل التنفيذ.
- مسار مسودة ← قيد التنفيذ ← تسليم ← مراجعات / اعتماد ← مكتمل.
- روابط HTTPS لملفات التسليم؛ لا تظهر للعميل قبل مرحلة التسليم؛ ويمكن للمدير سحب الروابط غير المنشورة.
- موجز للتحديثات الناتجة عن عمل المدير، متاح لصاحب الطلب فقط.
- صفحة إدارة الباقات وحالات الطلبات وسجل التغييرات، وملخص أرقام تجريبية وليس إيرادات.

## قيود مهمة

- **إضافة رابط HTTPS ليست رفع ملف إلى خادم منجاز.** الملفات يجب أن تكون موجودة مسبقًا لدى مزود تخزين، وصلاحيات الوصول إلى رابط الملف نفسه تعتمد على إعدادات ذلك المزود. لا تضع ملفات سرية في روابط مشاركة عامة.
- لا توجد عمليات خصم أو دفع حقيقي في هذه البيئة؛ `PAYMENT_MODE=mock`.
- عمليات الإنشاء والإدارة والتسليم مقيّدة بتطابق `APP_ENV=preview` ومعرّف مشروع Railway التجريبي الصحيح.
- اختبار واجهات API والوحدات وقاعدة PostgreSQL داخل CI لا يحل محل تجربة المتصفح بحساب عميل وحساب مدير.
- الحد الأقصى 25 رابطًا غير مسحوب لكل طلب؛ لا يمكن سحب رابط بعد نشره للعميل.
- لا تختبر بيئة الإنتاج بهذه الإعدادات، ولا تستخدم بيانات عملاء حقيقيين.

## الفحوصات الآلية

- **Unit tests:** `python -m unittest discover -s tests -p 'test_digital*.py' -v`
- **PostgreSQL integration:** `python scripts/test_digital_postgres_integration.py` — يعمل فقط في GitHub Actions باستخدام قاعدة `digital_test` محلية على `127.0.0.1:5432` وبحساب `postgres`.
- **Public read-only smoke:** `python scripts/smoke_digital_services.py` — يفحص الكتالوج والصلاحيات والصفحات بدون إنشاء طلبات.
- **GitHub Actions:** `.github/workflows/digital-services-preview-smoke.yml` — يفحص JavaScript وUnit وPostgreSQL وواجهات التجربة.

## قبل الانتقال للإنتاج
