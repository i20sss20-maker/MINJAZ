# MINJAZ — تجربة البريد بدون شراء نطاق (Resend)

> هذا الإعداد للتجربة **فقط** على مشروع Railway المعزول `MINJAZ-DIGITAL-SERVICES-TEST`. لا يُنشئ صندوق بريد خاص بمنجاز؛ `onboarding@resend.dev` عنوان اختبار مشترك تديره Resend وليس ملكًا لمنجاز. لا تصلح هذه الخطوة لإرسال رسائل إلى عملاء حقيقيين.

## المتطلبات التي لا يمكن توليدها آليًا نيابة عن مالك الحساب

1. صاحب المشروع ينشئ حسابًا في https://resend.com باستخدام بريده الإلكتروني الذي يستقبل عليه رسائل الاختبار.
2. ينشئ مفتاح API بإذن إرسال فقط. **لا يُنسخ المفتاح في الدردشة ولا في GitHub أو طلب دمج.** يُوضع مباشرة في متغيرات خدمة Railway التجريبية.
3. في إعدادات خدمة `minjaz-digital-services-api` داخل بيئة `sandbox` للمشروع **فقط**:
   - `EMAIL_MODE=resend`
   - `EMAIL_FROM=onboarding@resend.dev`
   - `RESEND_API_KEY=<secret from Resend, entered directly into Railway>`
   - `RESEND_TEST_RECIPIENT=<email that owns the Resend account>`
   - يجب أن يكون `APP_ENV=preview`، و`AUTH_SECRET` قويًا، و`PUBLIC_BASE_URL` رابط HTTPS الرسمي لنسخة الاختبار.
4. **لا تضف** `EMAIL_AUTH_REQUIRED=1` إلى الإنتاج بسبب الاختبار. لا تغيّر شيئًا في مشروع Railway الإنتاجي، ولا تعتمد تغييرات الخدمات المعلقة هناك.

## فحص الموصل دون إرسال

داخل بيئة الخدمة التجريبية المصرح لها بقراءة المتغيرات (ويمكن استخدام `railway run` مع **سياق بيئة تجريبية مضبوط** إذا كانت أسرار البيئة متاحة في ذلك السياق):

```bash
python scripts/probe_minjaz_resend_sender.py
```

سيعرض `ready` والحقول الناقصة بالأسماء **فقط**. لن يعرض المفتاح ولا عنوان المستلم، ولن يرسل رسالة.

## إرسال رسالة اختبار واحدة

بعد اكتمال الإعداد وتأكيد المستلم صاحب حساب Resend:

```bash
python scripts/probe_minjaz_resend_sender.py --send --confirm-sandbox-send
```

هذه الرسالة لا تحتوي رابط تفعيل حقيقي، ولا تنشئ مستخدمًا. نتيجتها `accepted_by_provider` تعني قبول Resend لطلب الإرسال **وليس إثبات وصوله إلى Inbox**. افتح بريدك وتحقق أيضًا من الرسائل غير المرغوب فيها. إذا رفضت Resend الطلب برمز `403` فتأكد أن عنوان المستلم هو نفس عنوان حساب Resend.

## تجربة تسجيل حساب منجاز من البداية للنهاية

1. بعد إثبات وصول رسالة الاختبار، افتح `/api/v1/auth/account-status` على موقع sandbox، وتأكد من `enabled=true` و`configured=true`.
2. أنشئ **حساب اختبار جديد فقط** من صفحة منجاز التجريبية باستخدام بريد حساب Resend نفسه، ورقم جوال للاختبار لا يرتبط بحساب آخر، وكلمة مرور قوية.
3. افتح رسالة «تفعيل حساب منجاز»، وانقر الرابط مرة واحدة، ثم اختبر دخول العميل وإنشاء مسودة خدمة، ولا تتوقع أي تحصيل مالي حقيقي.
4. اختبر إعادة إرسال التفعيل ورابط استعادة كلمة المرور. لا تشارك أي روابط تفعيل أو كلمات مرور أو بيانات عملاء في المحادثة.
5. جرّب المستقل في بيئة الاختبار، واختبر دخول الإدارة **فقط** بعد تخصيص بريد المدير المعتمد `ADMIN_EMAIL`. لا تمنح دور المدير بناءً على بريد غير مؤكد.

## بعد نجاح الاختبار

لإنشاء عنوان رسمي مثل `no-reply@YOUR-OWNED-DOMAIN`، يلزم امتلاك نطاق خاص بمنجاز وإثبات ملكيته عبر DNS في Resend. إرسال البريد باسم النطاق يتطلب تحقق النطاق، وقد يتطلب استقبال الرسائل صندوق بريد مستضافًا بصورة منفصلة. لا تستخدم `onboarding@resend.dev` كهوية رسمية ولا تعتمد هذا الفحص لإطلاق حسابات عامة.

لا تنشر تغييرات `main` أو بيئة Railway الإنتاجية قبل نجاح بوابة الإطلاق الكاملة، بما فيها حماية خصوصية الحسابات القديمة وحذف البيانات، وتسويات المدفوعات الحقيقية في المرحلة الأخيرة.
